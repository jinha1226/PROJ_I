## 1. 목표

**"내가 하는 게 없다"와 "캐릭터가 살아 있지 않다"를 함께 푼다.** 아래 고리가 돌아야 한다.

```
누구를 어디로 보낼지 정한다 → 던전에서 사건이 일어난다 → 캐릭터가 기억한다
→ 관계 · 대화 · 행동이 달라진다 → 그걸 보고 다음 편성과 원정을 정한다
```

플레이어가 "AI가 왜 저러지?"가 아니라 "저 둘은 지난번 일 때문에 저러는구나"라고 이해하면 성공이다.

첫 시제품은 **아스트랄 타워 하나**다. 다른 지역이나 모듈을 늘리지 않는다.

성공 기준은 낯선 사람이 시키지 않아도 **다음 원정을 누르는 것**이다. 테스트 통과는 필요 조건일 뿐이다.

### 예시 흐름

1. 원정 1: 금고 앞에서 마법사가 쓰러지고, 기사가 뛰어들어 끌어낸다. 궁수는 그사이 혼자 맞는다.
2. 귀환: 마법사는 기사를 믿고, 궁수는 기사를 원망한다. 관계 화면에 `금고 앞 구출 +8`이 남는다.
3. 캠프: 궁수가 "넌 쟤만 보이지?"라고 말한다.
4. 플레이어: 궁수를 또 보낼까, 빼고 로그를 고용할까?
5. 원정 2: 금고 앞에서 마법사가 그때 일을 꺼내고, 기사는 마법사 곁에 붙는다. 그 틈에 궁수가 위험해진다.

- PC 먼저 완성한다. 모바일은 완료 기준이 아니다.
- 스킬 AI 튜닝은 보류 중이다. `js/skill_ai.js`의 가중치를 다듬지 않는다.
- 아트는 CC0/CC-BY만 쓴다. 시나리오 지도 그림과 AI 이미지를 쓰지 않는다.
- **푸시는 사용자가 지시할 때만 한다.** 푸시 여부를 묻지도 않는다.
- 선택에는 플레이어 경험이나 참고 게임 근거를 댄다. 쉬워서 고르지 않는다.

### 같은 폴더 동시 작업

이 폴더는 git 저장소가 아니고, 여러 세션이 같은 파일을 동시에 고친다.

1. 고치기 직전에 그 부분을 다시 읽는다. 앞서 읽은 내용을 믿지 않는다.
2. 파일 전체를 덮어쓰지 않는다. 정확히 일치하는 문자열만 교체한다. 일치하지 않으면 다른 세션이 고친 것이니 다시 읽는다.
3. 큰 변경 전에는 `old/before_<작업명>/`에 복사해 둔다.
4. 다른 세션의 변경을 되돌리지 않는다. 시험이 깨지면 원인이 내 것인지 먼저 확인한다.
5. 내 묶음의 소유 파일이 아닌 곳은 짧은 연결 코드만 넣는다.
6. `pkill`을 넓은 패턴으로 쓰지 않는다. 다른 세션의 시험까지 죽는다.
7. 임시 파일은 자기 스크래치패드에 둔다.

### A. 탐험 방침

**원인:** `js/flow.js`의 `travel()`이 몬스터, 상자, 사건 칸이 있는 방만 목표로 삼는다. 빈 방은 안 가고 계단으로 간다.

- `f.explore`: `'full'`(꼼꼼히, 기본) 또는 `'fast'`(서둘러)
- 꼼꼼히: 갈 수 있는 방을 모두 들른 뒤에 계단으로 간다. 시간이 걸리는 대가는 기존 배회 몬스터와 자원 소모로 둔다.
- 서둘러: 지금의 목표 방식. 기존 `rt.rush`(바로 계단)와 구분한다.
- 계단 도착 시 안 간 방이 남으면 알린다: `안 간 방 3` + 내려간다 / 마저 본다. 기존 `S.ask` 질문을 쓰고, 기본값은 방침을 따른다.
- 잠긴 방과 비밀문 뒤는 갈 수 있는 방으로 세지 않는다.

**시험:** 꼼꼼히면 일반 층과 타워에서 갈 수 있는 방을 모두 들른다. 서둘러면 빈 방을 건너뛴다.

### B. 방 지시와 전투 지시

- 탐험 중 지도의 방을 누르면 그 방으로 간다: `rt.goRoom`. 도착하거나 전투가 나면 지시가 끝나고 방침으로 돌아간다.
- 갈 수 없는 방은 고를 수 없다. 이유를 아이콘으로 보인다(자물쇠 등).
- 안 누르면 멈추지 않고 방침대로 간다. 구경하는 재미를 지킨다.
- 방 사이 행동: 짧은 휴식, 귀환. 이미 있는 규칙을 버튼으로 연결한다.
- 전투 지시는 라운드당 하나다: 집중 공격(기존 `rt.focus`), 후퇴(기존), 주문 아끼기, 전력.
- 주문 아끼기와 전력은 슬롯 주문 사용 여부만 바꾼다. 수치를 건드리지 않고, AI 가중치도 다듬지 않는다.
- 지도 클릭은 `G.Cmd.click`이 이미 처리한다(몬스터 집중, 계단 서두르기, 파티원 상태창). 여기에 합친다. 따로 입력 처리를 만들지 않는다.

**시험:** 지시한 방으로 먼저 간다. 잠긴 방은 거부된다. 지시가 없으면 A와 동일하다.

### C. 기억과 관계

**지금 문제:** `js/bonds.js`는 같이 층을 내려가면 +1이고, 앙숙은 성격 조합으로 미리 정해지며, 전우에게 `피해 ×1.3`이 붙는다. 경험이 관계를 만들지 않고, 숫자 보너스는 SRD 원칙과 충돌한다.

기존 `f.saga`, `f.grudges`, `m.vow`, 사건의 `bondAB`, `bondWho`, `story.js`의 `campTalks`를 먼저 읽고 연결한다. 같은 일을 하는 저장소를 또 만들지 않는다.

**계약 (`G.Mem`, 세션 3이 이것에 의존한다. 바꾸면 이 문서도 고친다):**

```js
// f.mem = 최근 순 배열. 저장된다. 객체 참조 없음
{ id, t: 'rescue', a: uid, b: uid, run: 원정번호, fl, where: { scn, room, title }, w: 세기 }

G.Mem.add(f, rt, t, a, b, opts)   // 기록 + 관계 변화 + 스트레스 반응
G.Mem.of(f, uid)                  // 그 사람의 기억, 최근 순
G.Mem.between(f, a, b)            // 둘 사이 기억
G.Mem.at(f, where)                // 그 장소의 기억
G.Bond.score(f, from, to)         // from이 to를 어떻게 보나 (방향 있음)
G.Bond.why(f, from, to)           // [{ t, d, memId }] 변화 근거
G.Bond.rel(f, m1, m2)             // 기존 API 유지: 'friend' | 'foe' | null
```

**첫 사건 6종만 만든다:**

| t | 언제 | 관계 변화 (시험값) |
|---|---|---|
| `rescue` | a가 쓰러진 b를 구함 | b→a +8, a→b +2 |
| `abandon` | a가 쓰러진 b를 두고 감 | b→a −8 |
| `shielded` | a가 b 대신 맞음 | b→a +4 |
| `grab` | a가 전리품을 챙겨 b가 손해 | b→a −3 |
| `avenged` | a가 b를 쓰러뜨린 적을 잡음 | b→a +6 |
| `died` | a의 죽음을 b가 목격 | 대상 없음. 대사와 슬픔에 쓴다 |

**성격의 역할을 바꾼다.** 성격은 행동을 직접 정하는 대신 **사건을 받아들이는 방식**을 정한다. 다혈질은 원망이 크게 쌓이고, 온순은 감사가 크게 쌓이는 식이다. 기존 성격별 전투 행동은 지우지 말고 유지한다.

**바꿀 것:**
- 층 내려가기 +1 삭제
- 성격 조합으로 정해지는 앙숙 삭제. 첫인상 정도로만 약하게 남긴다.
- `FRIEND_DMG` 삭제. 연계기 쿨다운 배율도 검토한다(SRD에 없는 값이다).
- 상태창의 관계 칸에 현재 관계와 근거 표시: `전우 · 금고 앞 구출 +8`. 근거는 최근 2~3개만 보인다.

**시험:** 구출하면 구해진 쪽 점수가 오르고 근거가 남는다. 저장과 불러오기 후에도 유지된다. 같은 층에 있기만 해서는 변하지 않는다. 전우여도 피해가 같다.

### D. 관계에 따른 행동

C가 끝난 뒤에 한다. **행동의 선택만 바꾸고 수치를 바꾸지 않는다.** 반드시 일어나지 않고 확률로 일어난다.

| 상황 | 변화 |
|---|---|
| 동료가 쓰러짐 | 믿는 동료면 구하러 갈 확률이 오른다. 원망하면 내린다 |
| 진형 | 믿는 사람 곁에 서려 한다(`G.Tactics.slot`) |
| 표적 | 믿는 동료를 때리는 적을 먼저 친다 |
| 집중 지시 | 원망이 크면 가끔 따르지 않는다. 단장을 향한 관계만 본다 |

행동이 일어나면 왜인지 보여야 한다: 머리 위 짧은 표시와 전투 기록 한 줄. 안 보이면 없는 것과 같다.

**시험:** 같은 상황을 여러 번 돌려, 믿는 짝의 구출 비율이 원망하는 짝보다 높다. 체력과 피해 수치는 같다.

### E. 기억을 말하는 대사

C의 `G.Mem`만 읽는다. 대사는 `js/lines_memory.js`에 데이터로 둔다.

**대사가 나오는 곳:**
1. 같은 장소로 돌아왔을 때: `G.Mem.at`
2. 캠프와 귀환: 기존 `campTalks`에 연결한다. 둘이 사건을 두고 주고받는다.
3. 결정적 순간: 쓰러짐, 구출 직전

**분량:** 사건 6종 × 말하는 사람의 입장 × 관계 × 성격 축별로 쓴다. 이름, 장소, 적 이름을 넣어 **그 일에 대한 말**이 되게 한다. 일반 대사로 때우지 않는다.

**품질:**
- 같은 대사는 캠페인에서 반복되지 않게 기억한다(`m.said`).
- 말을 설명하지 않는다. "네가 날 구했으니 고마워" 대신 "그때 안 왔으면 난 거기 있었어."
- 기억이 없으면 그냥 말하지 않는다. 억지 대사보다 침묵이 낫다.
- 대사는 게임의 기존 말투(짧은 반말)에 맞춘다. `js/banter.js`를 먼저 읽는다.

**시험:** 모든 사건, 입장, 관계 조합에 대사가 있다. 이름 자리가 비지 않는다. 그 사건이 없는 사람은 그 대사를 말하지 않는다.

### F. 타워 재방문

**지금 문제:** 타워를 한 번에 끝까지 깬다. 상태도 `rt.scnS`에만 있어서 귀환하면 사라진다.

- 상태를 `f.scn.astral`로 옮긴다: 열린 문, 얻은 열쇠, 죽인 적, 연 상자, 정령 해방과 그 시계. 재방문하면 그대로 복원한다.
- 2~4번 왕복하게 한다. 원정의 자원(슬롯, 휴식)이 먼저 떨어지게 조정하되, 적 수치는 SRD 그대로 둔다. 조정값은 시험값으로 표시한다.
- **시신:** 죽은 용병의 시신과 장비가 그 자리에 남는다. 다음 원정에서 그 방에 가면 장비를 찾고, 이때 동료가 대사를 한다(E와 연결).
- **귀환 화면:** 얻은 것, 부상, 새로 안 사실, 못 연 것을 보인다. `금고 🔒 · 도둑 도구`처럼 **다음에 무엇을 데려갈지**가 드러나야 한다.
- **소문:** 출발 카드에 알려진 사실만 아이콘으로 보인다. 원정할수록 늘어난다. 기존 `js/lore.js`의 지식과 합친다.
- 아이템, 위치, 판정값은 `data/scenarios/astral_tower/`의 정규화 데이터를 따른다. 지어낸 내용은 `DESIGN.md`에 밝힌다.

**시험:** 귀환 후 재방문해도 문, 열쇠, 적이 유지된다. 시신에서 장비를 찾는다. 저장과 불러오기 후에도 같다.
